# 从修改到可用版本

这份说明是项目的当前操作入口。每次修改都走同一条路线：明确验收 → 修改 → 自动检查 → 人工试玩 → 发布核验 → 记录与维护。

## 当前状态

- 公开地址：https://prosperity-road-ial.bingkunq.chatgpt.site/
- 部署配置：`.openai/hosting.json`；静态目录：`dist/`。本次工作流建设不包含生产发布，现有线上提交尚未核验。
- 自动检查覆盖模型、存档恢复、六季主流程、试玩反馈、音频与音乐库；仍需在学校网络和学生设备上人工试玩。
- 下次业务验收参考 [学生试玩包](student-pilot.md)；《烟囱与河流》尚未接入可玩界面。

## 1. 开始修改

先用三句话写清：要解决的问题、可观察的完成条件、这次涉及哪些功能。在独立分支修改；保持已有存档兼容，涉及规则时同步更新对应剧本说明。

首次取代码并运行（Node.js 24.12+，npm、Git）：

```bash
git clone https://github.com/phytnesskun/prosperity-road.git
cd prosperity-road
npm ci
npx playwright install chromium
npm run dev
```

Linux/CI 将浏览器安装命令换成 `npx playwright install --with-deps chromium`。没有数据库或 API 密钥；游戏资产随仓库取得。本地音乐文件由玩家自行选择，刷新后需重新选择。

## 2. 自动检查与人工验收

```bash
npm run verify
npm run preview
```

`verify` 依次运行模型测试、类型检查与构建，再自动在回环地址的临时端口服务生产 `dist/`，运行四组浏览器检查。无需手动启动开发服务器；浏览器使用独立临时上下文。

检查结果见 `.qa/verification.json`，截图及下载证据也在 `.qa/`。任何失败都先修复；未执行的检查明确标为未验证。开发检查允许未提交改动，不能直接当作发布候选。

打开 `preview` 显示的地址，按本次验收条件试玩。基本路线为：查看正常市场 → 第二季选择政策并执行 → 试算 → 完成六季并下载战报；涉及反馈、音乐或顾问时补走对应路线。对规则变动核对数值和解释，对界面变动检查手机宽度。用测试存档验证刷新后继续游戏。

## 3. 准备并发布指定版本

提交改动并完成 PR 审阅；合并后，选定实际要发布的最终提交，在干净工作区执行：

```bash
npm ci
npm run verify:release
```

此命令要求 Git 工作区干净，生成包含提交、工作区状态及文件哈希的 `dist/release.json`，并检查这一份产物。只接受完整成功、提交与文件哈希匹配的发布候选。

GitHub Actions 使用同一命令并保存产物。选取最终发布提交对应的成功运行；PR 的临时合并提交或其他提交的检查不能代替它。保留完整 `dist/`、报告与来源提交，并在 CI 产物过期前另存一份已发布产物。

在发布已获授权时，通过现有 Sites 项目发布这份 `dist/`。发布前后都不要重新构建或修改其中的文件；如需修改，重新检查生成候选。CI 不自动发布。发布后执行：

```bash
npm run verify:live -- --url https://prosperity-road-ial.bingkunq.chatgpt.site/ --commit <40位提交SHA>
```

将 `<40位提交SHA>` 替换为实际提交。线上检查核对 `release.json`、资源哈希及最小玩家操作流程，使用独立浏览器上下文。旧网站缺少发布标记时不能确认提交，应记为未验证。自动检查通过后再用实际设备确认可用。

## 4. 记录、维护与恢复

在本次 PR 或发布记录留下这些信息，并更新 README 的当前状态：

```text
发布时间与网址：
源代码提交（40位 SHA）：
成功检查运行/报告与完整产物保存位置：
人工验收与线上核验结果：
已知问题、下一步：
上一可用产物位置（恢复用）：
```

出现阻断问题时，在相同网站地址重新部署上一份已验证且保留完整的产物，再用其提交运行 `verify:live`，记录恢复结果。恢复代码版本不保证恢复游戏存档；旧代码可能无法读取新格式，所以存档格式变更必须单独验证兼容与恢复方案。

进度与反馈草稿保存在各浏览器、各网址的 localStorage，没有服务器备份，也不会跨设备同步。Markdown 战报和反馈是可阅读记录，不是可导入恢复的存档备份。发布和排查时不得清除用户浏览器数据；“新任期”也不是修复或迁移办法。
